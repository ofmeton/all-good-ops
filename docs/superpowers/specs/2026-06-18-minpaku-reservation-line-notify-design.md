# 民泊アクティビティ予約通知 → LINEグループ自動通知 設計書

- 作成日: 2026-06-18
- ステータス: 設計承認済み（実装プラン未着手）
- 名義 / 領域: BEAT ICE（わたや Roopt葉山上山口）民泊オペレーション
- 関連: [[project_beatice_asia_expansion]] とは別件（こちらは予約オペ通知）

## 1. 目的

宿（BEAT ICE）の Gmail に「Roopt 運営」から届くアクティビティ予約通知メールを検知し、
**1予約（1組）あたり1通**に集約・整形して LINE グループへ自動通知する。完全無料で運用する。

### 解決する課題
- 1組がアクティビティを複数リクエストすると、リクエスト数ぶんのメールが**ほぼ同時に**届く（最大3通）。
- 同一リクエストの**重複メール**も届くことがある（同じ `r=` 値が複数通）。
- メールをそのまま転送すると LINE が複数通でうるさく、見落としにつながる。
- → 同一予約を束ね、重複を除き、1通の読みやすいサマリにする。

## 2. 要件（確定事項）

| 項目 | 決定 |
|---|---|
| トリガー方式 | Google Apps Script（GAS）の時間トリガー、1分毎ポーリング |
| 即時性 | 「最初のメール検知から2分後」に通知（数秒の即時は集約のため断念） |
| 集約待ち（グレース期間） | 2分 |
| 集約単位 | 1予約グループ = 1通 |
| LINE 送信 | LINE Messaging API（公式アカウント新規作成）の push message |
| 通知先 | LINE グループ（groupID を初回1回だけ取得して固定） |
| 通知内容 | 1組サマリ（生メール転送はしない） |
| 承認/NG リンク | ダッシュボードURL（全予約一覧）のみ |
| 「何もリクエストしない」回答 | 通知不要 |
| コスト | 完全無料（GAS/Sheets/Gmail）。LINE は月200通まで無料 |

## 3. 入力メール仕様（サンプルから確定）

送信者表示: `— Roopt 運営`（送信元アドレス・件名の正確な文字列は実装時に実物で確定）。
本文の特徴フレーズ: `下記のアクティビティ予約が入りました`。

### 抽出フィールド（本文の固定フォーマットから正規表現で抽出）

| フィールド | 抽出元 | 備考 |
|---|---|---|
| 集約キー | 承認URLの `r=` 先頭トークン | 例 `ac23a431`。**同一予約を束ねる主キー** |
| dedup識別子 | 承認URLの `r=` フル値 | 例 `ac23a431_tanada-ice_20260813`。完全一致は同一リクエスト＝重複 |
| アクティビティ名 | `■ アクティビティ:` 行 | 例「棚田米アイスづくりと野草茶体験」 |
| 体験日 | `■ 日付:` 行 | 例 2026-08-13 |
| 開催時間 | `■ 開催時間:` 行 | **体験ごとに異なる**（15:40~17:00 / 15:00~15:30） |
| 参加人数 | `■ 参加人数:` 行 | 表記ゆれあり（「大人3名/小学生1名(合計4名)」「4名」） |
| 料金 | `■ 料金:` 行 | **空欄/「（不明）」あり** → 欠損許容 |
| 氏名 | `■ 氏名:` 行 | 補助キー候補 |
| 電話 | `■ 電話:` 行 | |
| メール | `■ メールアドレス:` 行 | 補助キー候補 |
| 宿泊施設 | `■ 宿泊施設:` 行 | |
| 宿泊期間 | `■ 宿泊期間:` 行 | |
| 宿泊人数 | `■ 宿泊人数:` 行 | サマリの人数主表示に採用（例 大人3 子供1 幼児0） |
| ダッシュボードURL | `dashboard=1` を含むURL | 通知に載せる承認/一覧リンク |

### 集約キーのフォールバック
`r=` が取得できない場合は `氏名 + メールアドレス + 宿泊期間開始日` を結合したキーで束ねる。
それも不能ならパース失敗として扱う（§7）。

## 4. アーキテクチャ

```
Google Apps Script（宿の Google アカウント内・時間トリガー1分毎）
  ① Gmail検索   : 未処理の予約通知メールを取得（処理済みは Gmail ラベルで除外）
  ② パース      : r= で集約キー＆dedup識別子、本文から各フィールドを抽出
  ③ 集約        : 状態シートの予約グループ行へ体験を追記（dedup識別子で重複除外）
  ④ デバウンス送信: 初回検知 + 2分 ≦ now の予約グループを1通に整形
                   → LINE Messaging API push → 成功後に status=sent ＋ Gmail ラベル付与
        ↓
  LINE Messaging API（push message）→ LINE グループ
```

GCP / Pub/Sub / Cloudflare / 外部サーバーは一切不要。宿の Google アカウントと
LINE 公式アカウントだけで完結する。

### コンポーネント分割（単一責務）

| ユニット | 責務 | 依存 |
|---|---|---|
| `pollInbox()` | エントリポイント。1分毎に呼ばれ全体を順に実行 | 下記すべて |
| `fetchUnprocessed()` | Gmail 検索で未処理メールを返す | GmailApp |
| `parseReservationMail(message)` | 1通 → 構造化オブジェクト（失敗時 null） | なし（純関数） |
| `upsertBucket(parsed)` | 状態シートへ集約・重複排除 | SpreadsheetApp |
| `flushReadyBuckets()` | 2分経過バケットを整形・送信・確定 | SpreadsheetApp, sendLine, GmailApp |
| `formatSummary(bucket)` | バケット → LINE メッセージ文字列（純関数） | なし |
| `sendLine(text)` | LINE push 1回 | UrlFetchApp |

純関数（`parseReservationMail` / `formatSummary`）はサンプルメールを使った
単体テスト（GAS 内テスト関数 or clasp+ローカル）で検証可能にする。

## 5. 状態ストア = スプレッドシート（1枚）

1行 = 1予約グループ。状態管理とログ（予約履歴）を兼ねる。

| 列 | 内容 |
|---|---|
| `reservation_key` | 集約キー（例 ac23a431）。主キー |
| `first_seen_at` | 初回検知時刻（ISO）。デバウンス起点 |
| `customer` | 氏名 / 電話 / メール |
| `stay` | 宿泊施設 / 期間 / 人数 |
| `activities_json` | 体験リスト [{dedup_id, name, date, time, fee, headcount}]（dedup_id で重複除外） |
| `dashboard_url` | 承認/一覧リンク |
| `processed_message_ids` | 取り込み済み Gmail messageId（カンマ区切り） |
| `status` | `pending` / `sent` |
| `sent_at` | 送信時刻 |

Properties Service ではなくシートを採用する理由: デバッグ容易・予約履歴が残り宿側が見返せる・
サイズ制限が緩い。

## 6. LINE 通知フォーマット（確定案）

```
🏡 新しいアクティビティ予約（要承認）

👤 Tanaka Asami 様 / 大人3・子供1（宿泊人数）
🏠 わたや Roopt葉山上山口
🗓 宿泊 8/13〜8/14

🎯 リクエストされた体験（3件）
 ・棚田米アイスづくりと野草茶体験  8/13 15:40〜17:00  ¥12,500
 ・棚田と里山の農作業体験        8/13 15:40〜17:00  ¥12,500
 ・棚田散策                    8/13 15:00〜15:30  ¥-
💴 合計 ¥25,000（料金記載分のみ）

✅ 承認/NG・予約一覧:
<ダッシュボードURL>
```

- 体験ごとに時間・料金を併記。料金欠損は `¥-`、合計は記載分のみ＋注記。
- 人数は宿泊人数を主表示（参加人数の表記ゆれを避ける）。

## 7. エラー処理 / 取りこぼし防止

- **送信成功してから確定**: LINE push が 200 を返してから status=sent ＋ Gmail ラベル付与。
  失敗時は pending のまま＝次回実行で自動リトライ（ラベルも付けない）。
- **パース失敗**: `r=` も補助キーも取れない／本文崩れ等は、**生メールの件名+本文を
  そのまま LINE に流す**＋専用エラーラベルを付与。握り潰さず必ず人の目に入れる。
- **二重送信防止**: `processed_message_ids` と Gmail ラベルの二重ガード。
- **無限滞留防止**: pending が一定回数（例: 10回 = 約10分）リトライ失敗したバケットは、
  エラー通知（生情報）を1度出して status=failed に落とし、滞留させない。

## 8. 初期セットアップ（1回だけ・人手）

1. LINE Developers で Messaging API チャネル（公式アカウント）を新規作成。
2. 公式アカウントを通知先 LINE グループに招待。
3. GAS を Webhook URL に設定 or グループで一度発言させ、`source.groupId` を1回取得して
   スクリプトプロパティに固定（以降 Webhook は不要、push のみ）。
4. チャネルアクセストークンをスクリプトプロパティに格納。
5. 状態シートを作成し ID をプロパティに格納。
6. `pollInbox` の時間トリガー（1分毎）を設定。
7. Gmail 検索クエリ（送信元/件名）を実物メールで確定。

## 9. コスト・制約（明示）

- GAS / スプレッドシート / Gmail: **完全無料**。
- LINE Messaging API: **フリープランで月200通まで無料**（1組1通＝月200組まで無料）。
  超過時は有料プラン（月額〜5,000円規模）が必要。民泊規模では当面無料枠で足りる見込み。
- GAS 実行時間クォータ（無料: 1日90分等）内に余裕で収まる軽量処理。

## 10. スコープ外（YAGNI）

- 承認/NG の自動処理（リンクを踏むのは人手のまま）。
- 予約のキャンセル/変更メールの差分通知（初回リクエスト通知のみ）。
- 多施設・多事業者対応（まず BEAT ICE / わたや 単一構成）。
- 数秒レベルの即時通知（集約要件と両立しないため不採用）。
