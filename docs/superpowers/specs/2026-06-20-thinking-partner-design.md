# 思考パートナー（思考版ジャーナリング）設計

> 2026-06-20 / ofmeton（陸さん個人運用）

## 背景・課題

「考えなきゃ」と思いつつ考えられないテーマがある。種類は判断・意思決定／戦略・長期の問い／アイデア・構想の深掘り／内省と多岐にわたるが、**ジャンルが問題ではなく、考えるという行為が外部の器に乗っていない**のが本質。タスクは hermes、感情・内省は journaling に器があるのに、「考えるべきテーマ」だけが頭の中の一過性イベントのまま無宿になっている。

詰まりは4つの関所すべてで起きている：

| 関所 | 症状 |
|---|---|
| 捕捉 | 「これ考えなきゃ」と思った瞬間はあるが、メモせず流れ、存在を忘れる |
| 着手 | 考えるべきことは覚えているが、時間・場面を作れず後回し |
| 起動 | 向き合っても、何から考えればいいか分からず空回り |
| 完結 | 考えはするが結論・次の一手に落ちず、同じところをぐるぐるして貯まらない |

## ゴール

思考を **捕捉 → 置き場 → 起動 → 完結** まで運ぶ1本のループを外部に敷く。各関所に1対1で器を当てる。考え方は **Claudeとの対話**、引き出しは **定期リマインド（毎朝）**。

journaling の成功した型を土台にした「双子」として作る。ただし1点だけ決定的に違う：

- **journaling = 答えを出さない聞き役**（軽くするのをゴールにしない、重いまま持ち帰る）
- **思考パートナー = 結論／次の一手まで押し込む伴走**（痛点が「考えっぱなし」だから、完結に責任を持つ）

## 非ゴール（YAGNI）

- 専用ダッシュボード／状態可視化アプリは作らない（個人用に過剰・保守負債）
- 完結率などの定量メトリクスは追わない
- 内省・感情の深掘りはここではやらない（journaling へ送る・越境しない）

## アーキテクチャ

### データの置き場

思考の"見出し"（低機微）と"中身"（私的）を分離する。

| 物 | 置き場 | 性質 |
|---|---|---|
| 思考パートナーの役割・型・方針（SSOT） | `~/journal/think/CARTE.md` | git管理外・起動時必読 |
| 思考テーマのインボックス | Phase1: `~/journal/think/inbox.md` ／ Phase2: Notion「思考インボックス」DB | 見出しのみ・低機微 |
| 1セッションの記録（対話の結論） | `~/journal/think/entries/YYYY-MM-DD-<slug>.md` | git管理外・私的 |

`~/journal` は journaling と同じく **git管理外・リポジトリ外**。git push 対象（`raw/facts/`・`outputs/`・wiki）に思考の中身を書かない。

inbox の状態マーク：`[ ]` 未着手 / `[~]` 思考中 / `[x]` 完結。

### 各関所の仕掛け

| 関所 | 仕掛け |
|---|---|
| 捕捉 | 「考えたい：〇〇」と一言 → inbox に1行追記するだけ（評価・着手はその場でしない、放るだけ）。Phase2 で Telegram からも投入可 |
| 着手 | 毎朝の cloud routine が「思考タイムどう？」と一声（journaling の22:00とずらす・強制しない・スキップOK） |
| 起動 | `/think`（skill）起動 → CARTE読込 → inbox から1テーマを提示し、最初の問いをこちらから置く（白紙を渡さない） |
| 完結 | 対話の最後に必ず **結論 / 次の一手 / 次に考える問い** のどれかを言語化 → entries に記録 → inbox の状態を進める |

### 対話のスタイル（CARTE に明記する核）

- **目的は結論への前進**。journaling と違い「考えっぱなし」で終わらせない。一区切りで必ず何かに落とす
- grill-me 式に前提・抜け・反例・機会費用を突く。ただし詰問でなく一緒に考える伴走トーン
- テーマ種別で深さを変える：
  - 判断・意思決定 → 選択肢と決め手（基準）を明確化し、保留してる理由を言語化
  - 戦略・長期の問い → 問いそのものを再定義してから考える
  - アイデア・構想 → 発散させてから1個に絞る
  - 内省・自分の状態 → journaling 側へ送る（ここでは深掘りしない）
- いつもの思考ループをぐるぐるしてると感じたら、ルートから外れる問いを差し込む（journaling から継承）
- 答えを押し付けない。決めるのは本人。Claudeは根拠と問いをセットで返す

### 起動導線

skill `thinking` を「考えたい」「思考タイム」「頭の棚卸し」「思考する」「これ考えなきゃ」等で起動。CARTE.md を読んで思考パートナーモードに入る。仕事の振り返り（session-retrospective）・感情の内省（journaling）とは別物。

## フェーズ分割

### Phase 1（MVP・クラウド非依存・まず1人で回す）

1. `~/journal/think/CARTE.md` 作成（役割・型・対話スタイル・テーマ種別ガイド・entry索引）
2. `~/journal/think/inbox.md` 作成（空のインボックス・状態マーク凡例）
3. `.claude/skills/thinking/SKILL.md` 作成（起動時手順・対話の核・記録手順・プライバシー）
4. 毎朝の cloud routine 作成（claude.ai/code/routines。journaling と同型の一声ナッジ）
5. 捕捉導線：「考えたい：〇〇」をローカル inbox.md に追記する運用を CLAUDE.md に1行追加

検証：実際に数テーマ捕捉 → 朝ナッジ → `/think` で対話 → entries に結論が落ちる、を1周回す。

### Phase 2（Telegram 捕捉・クラウド配線）

1. Notion「思考インボックス」DB 作成（見出し・状態・捕捉日のみ）
2. hermes の Telegram 受けに思考捕捉ルートを追加（`考えたい：` プレフィックス等で task でなく思考インボックスへ振る）
3. skill が Notion インボックスとローカル inbox.md の両方を読むよう更新
4. 完結時に Notion 側の状態も done に更新

注：Phase2 は hermes（GCP VM）改修を伴う。MVP の実証後に着手。

## プライバシー（厳守）

- 思考の中身（対話・結論）は `~/journal/think` のみ。git push 対象に出さない
- 完結内容が契約・案件の**事実決定**の場合のみ、その時に「raw に記録する？」と確認して `raw/facts/` へ昇格（自動ではしない）
- journaling と同じ私的領域の扱い。CLAUDE.md「事実情報の自動 raw 保存」の例外
